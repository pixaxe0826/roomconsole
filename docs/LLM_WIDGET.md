# LLM 응답 위젯 — Room Hub 0.1.4 추가 기능

패치 식별자: `room-hub-0.1.4-llm-widget1`. 앱 버전은 0.1.4를 유지합니다.
이 문서의 예시 응답은 합성 데이터이며 실제 LLM 성능/정확도 결과가 아닙니다.

## 화면과 동작

`widgets/llm-response/`는 기존 위젯 API v1 폴더입니다. 기본 크기는 가로 4 × 세로 2입니다.
위에는 이름·전송 시각·확대 버튼, 가운데에는 **보낸 사용자 요청 / LLM 최종 응답**을
나란히, 아래에는 **이전 / 현재 순번·전체 수 / 다음**을 표시합니다.

- 한 위젯에 한 요청·응답만 보입니다. 각 재요청은 별도 기록입니다.
- 왼쪽 화살표는 이전(더 오래된 전송), 오른쪽은 다음(더 최근 전송)입니다. 끝에서는 비활성화합니다. 순환 이동하지 않습니다.
- 첫 진입은 가장 최근 전송입니다. 최신 보기 상태에서는 새 전송/응답을 따라갑니다.
- 이전 기록을 읽는 동안에는 새 기록이 추가되어도 선택을 바꾸지 않습니다. `최신으로`를 누르면 복귀합니다.
- 탐색 위치는 위젯 인스턴스별 메모리에만 보관합니다. 새로고침하면 최신부터 시작합니다.
- 본문이나 확대 버튼을 누르면 한 쌍을 크게 표시합니다. 위쪽 `뒤로` 버튼은 기본 화면으로 돌아갑니다.
- 4×2에서는 긴 내용 일부만 표시합니다. **확대 화면에서 요청/응답 각각 스크롤**하여 전체 저장 내용을 확인합니다.
- 서버가 전역 상태를 갱신해도 현재 항목과 확대 화면의 스크롤을 보존합니다.
- 4×2보다 작은 공간은 요약 형태입니다. 아주 작은 1×1 영역에서는 확대하여 탐색하세요.
- 결과는 문자열 그대로 안전하게 표시합니다. Markdown/HTML 실행, 링크 자동 실행, 도구 실행은 하지 않습니다.
- 토큰/성능 통계, System 메시지, 실제 전체 API JSON은 기존 관리자 LLM 화면에만 남깁니다.

## 어떤 기록을 보여 주는가

서버의 `dispatch_attempted=1`이고 `started_at`이 있는 **실제 HTTP 전송을 시도한 기록**만 대상입니다.
이는 LLM 서버가 성공적으로 수신했다는 보증은 아닙니다. 전송 실패도 상태를 구분해서 보여 줍니다.

| 상태 | 위젯 |
|---|---|
| 미전송 / 모델 연결 대기 | 제외 |
| 아직 HTTP 전송을 시도하지 않은 대기열 | 제외 |
| 전송 전에 취소/서버 중단 | 제외 |
| 전송 후 응답 대기 | 사용자 입력 + `LLM이 응답을 준비하고 있습니다` |
| 응답 성공 | 사용자 입력 + 저장된 최종 응답 |
| 실패 / 취소 / 중단 | 사용자 입력 + 해당 상태 안내. 원시 오류나 내부 경로는 전달하지 않음 |
| 최종 답변 없이 tool-call만 반환 | 실행하지 않았다는 안내. 도구 내용은 전달하지 않음 |
| 별도 reasoning만 있고 최종 답변 없음 | 최종 답변이 없다는 안내. reasoning은 전달하지 않음 |
| 출력 한도 종료 | 확대 화면에 답변이 잘렸을 수 있다는 표시 |

**아직 모델을 연결하지 않았다면 현재 관리자에서 보이는 ‘미전송 · 모델 연결 대기’ 기록이 있어도
클라이언트는 ‘아직 전송된 요청이 없어요’라고 표시하는 것이 정상입니다.**
이번 패치는 LLM이나 모델을 설치하거나 미전송 항목을 자동으로 보내지 않습니다.

기록은 생성일이 아닌 실제 전송 시작 시각, 동률이면 ID 순으로 정렬합니다.
서버의 기존 최대 1,000개 LLM 기록 모두 접근 가능하며 임의로 최근 10개만 자르지 않습니다.
원본 음성 삭제나 전사문 수정은 기존 LLM 스냅샷을 바꾸지 않습니다. LLM 기록 자체를 삭제하면
연결된 화면이 다음 서버 갱신을 받을 때 목록에서 사라집니다.

## 공유 범위와 권한

**관리자가 공유 레이아웃에 `LLM 응답` 위젯을 추가하는 동작이 표시 기기 공유의 명시적인 시작입니다.**
이 허브는 개인 작업 공간 하나를 여러 화면이 공유합니다. 위젯을 추가하면 **모든 유효한 표시 기기**가
모든 출처의 전송된 요청·최종 응답을 볼 수 있습니다. 원본 음성에 대한 기기별 접근 제한은 유지합니다.
원하지 않으면 위젯을 배치하지 마세요. 위젯을 전부 제거하면 새 조회가 차단됩니다.
오프라인 기기는 삭제·공유 해제를 즉시 전달받지 못하므로 기존 화면을 마지막 데이터로 표시할 수 있습니다.
이미 전달된 텍스트나 사용자가 별도로 저장한 화면까지 원격으로 회수하는 기능은 아닙니다.

다음은 표시 기기에 제공하지 않습니다.

- System 입력, 기준 시각을 포함한 전체 prompt/messages/원시 요청 JSON
- reasoning, tool_calls 원문, 백엔드 원시 응답, 토큰 통계
- API 엔드포인트, 관리자/입력 키, 인증 헤더, 요청 해시와 원본 기기 정보
- LLM 생성·재시도·취소·삭제·설정 권한

기존 `/api/llm/*`는 계속 관리자 전용입니다. 표시 기기는 새 읽기 전용 투영만 사용합니다.
위젯 JS는 다른 기존 위젯처럼 신뢰된 동일 출처 코드이며 별도 보안 샌드박스가 아닙니다.

## 서버와 클라이언트 API

`GET /api/state` (기존 viewer 인증)에 다음이 추가됩니다.

```json
{
  "capabilities": {"llm_response_widget": true},
  "llm_display": {
    "enabled": true,
    "total": 1,
    "items": [{"id":"example-id","status":"succeeded","sent_at":"2026-09-20T00:00:00+00:00","updated_at":"2026-09-20T00:00:03+00:00"}]
  }
}
```

위젯이 배치되지 않았으면 enabled=false, items=[], total=0입니다. 인덱스에는 입력/응답 본문이 없습니다.

`GET /api/display/llm/{id}` (viewer 인증 + 위젯 공유 활성화 확인)는 **선택한 한 건**만 반환합니다.

```json
{
  "id":"example-id", "status":"succeeded", "sent_at":"2026-09-20T00:00:00+00:00",
  "updated_at":"2026-09-20T00:00:03+00:00", "finished_at":"2026-09-20T00:00:03+00:00",
  "model":"example-model", "input":"예시 요청", "output":"예시 답변", "refusal":null,
  "output_kind":"text", "truncated":false
}
```

401=로그인/표시 세션 없음·만료·해제, 403=공유 위젯 미배치, 404=삭제됨/미전송/없는 기록입니다.
응답은 no-store입니다. input은 전송 때 저장된 사용자 텍스트이며 System 메시지와 다릅니다.
원래 입력/최종 응답 문자열은 서버에서 임의로 자르지 않습니다. 별도 reasoning만 자동 합치지 않습니다.

서버의 기존 invalidate 알림과 30초 상태 폴링으로 인덱스를 갱신합니다. 실제 dispatch 후 알림을
하나 추가하여 긴 생성 중에도 ‘응답 대기’를 표시합니다. 선택한 항목의 버전이 같으면 GET을
반복하지 않습니다. GET은 10초 제한, 실패 시 명시적인 다시 조회 또는 다음 서버 스냅샷에서
재시도합니다. **이는 조회 재시도이지 LLM 생성 재요청이 아닙니다.**

## 소스 변경

- `app/llm_display.py`: 입력/출력 allowlist 투영, 공유 범위 검사. 신규 DB 테이블 없음.
- `app/main.py`: state 인덱스와 읽기 전용 endpoint.
- `app/llm.py`: 전송 시도 플래그 저장 후 invalidate 알림 한 번 추가. 모델/옵션/전송 횟수 변경 없음.
- `web/client.js`: 위젯 컨텍스트에 `isDemo`, `connected` 전달. 기존 음성·완료 로직 그대로.
- `web/client.html`: 캐시 식별자.
- `web/manager.js`, `web/manager.html`: 새 위젯의 공유 설명 및 캐시 식별자. 기존 QR/크기 수정 유지.
- `widgets/llm-response/*`: 위젯 자체.

**`app/speech.py`, speech-config.json, 모델, 엔진, 서비스·Android 설정, HTTPS, 세션은 수정하지 않습니다.**
