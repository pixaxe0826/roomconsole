# 메모·알람 — Room Hub 0.1.7

0.1.6에 저장형 메모와 서버 예약 알람을 추가합니다. 모델·Whisper·음성 입력·TLS·서비스 설정을 바꾸지 않습니다. 기존 배치도 자동으로 변경하지 않습니다.

## 메모

관리자 **메모**에서 제목·내용을 만들고 수정·삭제하며, 제목/내용 검색과 위에 고정을 사용할 수 있습니다. 최대 200개, 제목 120자, 본문 8,000자입니다. 기본은 비공개이며 **iPad에 표시**를 켠 항목만 `note` 위젯에 전달됩니다. 위젯이 배치되어 있지 않으면 공유 메모도 표시 기기 DTO에 넣지 않습니다. 비공개 제목·본문·개수는 표시용 API에서 제외합니다.

기존 `note` ID를 유지합니다. 예전에 위젯 설정이나 `widget_data:note.text`로 저장한 고정 문구는 첫 카드로 보존하고 새 메모와 구분합니다. 이를 새 DB에 임의로 복제하거나 기존 설정을 비우지 않습니다. 기존 고정 문구를 없애려면 원래 위젯 설정/위젯 데이터에서 직접 지우세요. 새 메모의 비공개 토글은 이 기존 고정 문구를 숨기지 않습니다.

iPad는 앞/뒤 버튼으로 메모를 탐색하고, 위젯을 터치하여 확대합니다. 편집·삭제는 관리자 전용입니다. 공유하는 순간 같은 영구 배치를 사용하는 모든 연결 화면에 보입니다. 프런트엔드는 텍스트를 escape하고 줄바꿈을 보존합니다.

## 알람

관리자 **알람**에서 한 번 / 매일 / 평일 / 선택 요일을 예약합니다. 저장된 예약은 최대 64개이며 각각 IANA 시간대가 있습니다. 허브의 전역 시간대를 바꿔도 이미 저장한 예약의 시간대는 유지됩니다. 요일 저장 규약은 월=0 … 일=6입니다. 한 번 알람의 날짜는 1970~2100년이며, 켤 때는 미래 시각이어야 합니다.

`alarms` 위젯 기본 크기는 4×2입니다. 다음 알람, 남은 예약, 미룬 회차, 놓친 알람을 보여줍니다. 확대 후 더 보기로 전체 예약을 탐색할 수 있습니다. 예약은 관리자에서만 생성·변경·삭제합니다. iPad에서는 **이미 발생한 회차**의 확인·종료 또는 5분 미루기만 가능합니다. 미루기는 한 회차에 최대 3번입니다. 여러 화면 중 한 곳에서 확인하면 공유 상태가 종료됩니다. 알람 위젯 배치가 사라지거나 표시 세션이 취소되면 표시용 권한도 사라집니다.

서버는 1초 주기로 SQLite 예약을 확인합니다. 실제 변경이 있을 때 기존 WebSocket invalidate를 보내며, 열린 알람 화면은 5초 주기 읽기도 사용합니다. 스케줄러는 가중치/LLM을 호출하지 않습니다. 네트워크 단절 또는 15초 이상 새 스냅샷이 없으면 화면의 울림을 억제합니다. 상태는 일관된 DB 읽기와 별도 단조 증가 revision으로 오래된 응답의 역전을 막습니다.

### 소리·절전의 경계

실제 iPad의 `/client`에서 **소리 허용·테스트**를 직접 누르고 테스트 음과 기기 음량을 확인하세요. 자동 재생을 약속하지 않습니다. 브라우저 AudioContext의 running 상태는 API 상태일 뿐, 사용자가 소리를 들었다는 증거가 아닙니다. 서버의 `ringing`은 **울림 대기**라는 뜻이고 `sound_confirmed`는 항상 false입니다.

페이지가 열리고 활성 상태이며 서버에 연결된 동안, 허용한 WebAudio로 짧은 2음 알람을 반복합니다. 새로고침 뒤에는 다시 허용해야 합니다. 관리자 iframe과 독립 데모에서는 소리를 재생하지 않습니다. 음소거는 해당 화면의 소리만 끄며 예약 자체를 끄지 않습니다.

**잠긴 iPad, 닫힌 Safari, 백그라운드 페이지, 절전된 V35, 꺼진 서버, 오프라인에서 정확한 울림을 보장하지 않습니다.** 네이티브 알람·Web Push·서비스워커·화면 강제 켜기는 구현하지 않았습니다. 기상·복약 등 놓치면 안 되는 용도는 별도 시스템 알람을 함께 사용하세요.

### 늦은 실행·재시작·서머타임

예정 시각보다 5분 이내 늦게 서버가 처리하면 현재 시점에서 최대 2분 동안 울림 대기입니다. 5분 넘게 지났다면 놓친 알람으로 남기고 뒤늦게 계속 울리지 않습니다. 울림 대기를 2분 동안 확인하지 않으면 놓친 알람이 됩니다. 미룬 회차에도 같은 지연 정책을 적용합니다.

장시간 중단 후 반복 알람은 최초 미처리 회차 하나만 놓친 기록으로 남기고, 다음 미래 시각으로 이동합니다. 과거 일수만큼 소리를 몰아서 재생하지 않습니다. `(alarm_id, scheduled_at)` 유일성, 트랜잭션, 요청 영수증으로 재시작과 중복 확인을 방어합니다. 생성 요청/확인/미루기는 동일 request_id 재전송 시 다시 실행되지 않습니다. 삭제된 항목도 늦은 재시도로 복구되지 않습니다.

예약을 수정/끄면 그 예약의 울림·미루기·놓친 회차는 취소됩니다. 예약을 삭제하면 해당 회차 기록도 함께 제거합니다. 최신 기록 최대 100개를 유지하되 활성 울림/미루기는 정리 대상에서 제외합니다. 관리자 기록과 표시 목록은 구분됩니다. 요청 중복 방지 영수증은 최대 10,000개이며 한도에 도달하면 조용히 삭제하지 않고 점검을 요구합니다.

서머타임에서 한 번 예약의 존재하지 않거나 두 번 있는 로컬 시각은 거부합니다. 요일 반복은 사라진 시각의 해당 날짜를 건너뛰고, 중복 시각은 첫 번째만 사용합니다. 서버 OS 자동 날짜·시간 설정의 정확성은 별도 조건입니다.

## 음성 비서와의 구분

**이번 릴리스는 위젯과 관리자 서비스를 연결하며, 음성으로 메모/알람을 실행하는 LLM 도구는 추가하지 않습니다.** `메모 저장해 줘`, `알람 설정해`는 관리자 메뉴 사용을 안내하고 실행했다고 주장하지 않습니다. 기존 할 일 비서의 확인·스냅샷·영수증 정책은 그대로입니다. 향후 음성 기능은 별도의 허용 스키마·확인 화면·중복 방지 테스트가 필요합니다.

## API와 저장

`GET /api/life/display`는 인증된 viewer의 최소 표시 DTO입니다. `GET/POST /api/life/notes`, `PUT/DELETE /api/life/notes/{id}`, `GET/POST /api/life/alarms`, `PUT/DELETE /api/life/alarms/{id}`는 관리자 전용입니다. `POST /api/life/events/{id}/ack|snooze`는 관리자 또는 알람이 배치된 유효 표시 세션에 한정합니다. 변경 요청은 기존 same-origin/CSRF 정책을 그대로 적용합니다. 수정·삭제·회차 동작은 version 충돌 시 409입니다.

기존 SQLite에 `hub_notes`, `hub_alarms`, `hub_alarm_events`, `hub_life_receipts`, `hub_life_meta`를 추가합니다. 기존 테이블/행을 삭제하거나 모델 설정을 마이그레이션하지 않습니다. 관리자 JSON 내보내기에 메모·예약·최근 회차를 추가했고, 원래 DB 백업에는 새 테이블도 포함됩니다. 내보내기는 개인 자료이며 GitHub에 올리지 마세요.
