# Room Hub 0.1.4 — 관리자 LLM 인터페이스

## 목적과 범위

음성 입력 → 기존 V35 전사 → **음성 수신함 저장** → 사용자가 **LLM으로 전송** → 요청별 입력·출력·성능 기록.

이번 업데이트는 Qwen/llama.cpp 설치·모델 다운로드·모델 프로세스 시작을 하지 않습니다. Whisper 모델/스레드/시간 제한, iPad 마이크·인증서·페어링, nginx·Tasker·Wake Lock 설정도 바꾸지 않습니다. 기존 Base/6T 설정은 그대로입니다.

LLM은 앞으로 V35 내부 `http://127.0.0.1:8090/v1`에서 실행할 수 있도록 준비합니다. **지금 8090 포트를 새로 열지는 않습니다.** 앱의 기존 포트는 HTTP 8088 / HTTPS 8443입니다. 기본 LLM 전송 스위치는 꺼져 있습니다.

## 사용 흐름

1. iPad에서 기존 방법으로 녹음·전사합니다.
2. Windows 관리자 → **음성 수신함**에서 전사문을 확인합니다.
3. 전사문을 수정했다면 먼저 **전사 저장**을 누릅니다. 저장하지 않은 내용을 묵시적으로 전송하지 않습니다.
4. **LLM으로 전송**을 누릅니다. 전사가 진행 중이거나 저장된 텍스트가 없으면 비활성화됩니다.
5. 별도 **LLM 인터페이스** 메뉴로 이동합니다. 입력당 요청을 구분하고, 같은 입력 재요청은 새 기록으로 남깁니다.
6. 처음에는 **미전송 · 모델 연결 대기**입니다. 입력 JSON만 보관하고 출력·토큰 수·시간은 `—`로 둡니다.
7. 향후 실제 LLM 서버를 준비하고 연결 설정을 켠 뒤 저장된 입력을 직접 전송합니다. 연결을 켜는 것만으로 과거 입력을 일괄 전송하지 않습니다.

전사나 LLM 응답으로 할 일을 자동 생성·변경·삭제하지 않습니다. 반환된 `tool_calls`도 표시만 하며 실행하지 않습니다.

## 화면

- 왼쪽: 요청 시간·전사문·상태·모델·기본 성능 요약. 검색, 상태 필터, 음성 원본별 필터, 30개 단위 이전/다음 탐색.
- 오른쪽: 요청 식별자, 시간/토큰 카드, 입력 스냅샷, System 입력, 정확한 API 요청 JSON, LLM 출력, 상세 통계와 원본 JSON 응답.
- 하단: 저장된 입력 전송, 현재 설정으로 새 요청, 취소, 개별 JSON 내보내기, 기록 삭제.
- 설정: loopback API 주소·모델 ID·System prompt·최대 출력 토큰·temperature·시간 제한·non-thinking 요청.

입력은 당시의 전사문을 그대로 저장합니다. 음성 수신함의 텍스트가 나중에 수정되어도 이전 기록은 바뀌지 않습니다. 재요청은 **이전 전사문 + 현재 설정 + 새 기준 시각**으로 만듭니다. 원본을 수정한 새 내용으로 보내려면 음성 수신함에서 다시 보내세요.

자동 갱신과 메뉴 이동에서 선택한 기록/입력 초안/펼쳐 둔 상세 구간을 가능한 한 유지합니다. **입력·출력 기록은 SQLite에 영구 저장**하므로 브라우저 재시작 뒤 다시 조회할 수 있습니다. 미저장 설정 초안은 브라우저 메모리에만 있으므로 전체 새로고침하면 사라집니다.

## '실제 입력'의 정확한 범위

저장/내보내는 `request_body`는 Room Hub가 HTTP에 전달하는 **UTF-8 JSON 본문 원문**입니다. `messages`(system/user), 모델 ID, 생성 옵션, 기준 시각을 모두 포함하고 SHA256을 같이 저장합니다. 인증 헤더는 저장하지 않습니다.

미전송 단계에는 **전송할 입력**으로 표시합니다. `dispatch_attempted`는 HTTP 전송을 시도했다는 뜻이지 상대 모델이 반드시 입력을 소비했다는 보장은 아닙니다. 실패 시에도 이를 구분합니다.

이는 백엔드의 chat template으로 확장한 최종 토큰열을 뜻하지 않습니다. 백엔드의 템플릿·토크나이저 내부 변환은 이 버전에서 수집하지 않습니다.

## 시간과 토큰 지표

| UI 지표 | 실제 의미 | 미제공/미실행 때 |
|---|---|---|
| 응답 수신까지 | Room Hub의 HTTP 호출 시작 → 응답 전체 수신. 대기열·음성인식·브라우저 표시 시간 제외 | `—` |
| 출력 토큰 | `usage.completion_tokens`; 없을 때 `timings.predicted_n` | `—`, 글자/단어 수로 추정 안 함 |
| 입력 토큰 | `usage.prompt_tokens` | `—` |
| 토큰 생성 속도 | 백엔드의 `timings.predicted_per_second`, 또는 `predicted_n/(predicted_ms/1000)` | 생성 통계가 없으면 `—` |
| 순수 생성 구간 | `timings.predicted_ms/1000` | `—` |
| 요청 전체 기준 처리율 | 출력 토큰 / 응답 수신까지의 시간 | 상세 영역에만 표시. 순수 생성 속도와 다름 |
| 대기열 | 큐 접수 후 worker 시작 전 대기 | 미접수 시 `—` |

공급자가 보고한 토큰 수는 EOS·reasoning 등의 포함 규칙이 달라질 수 있습니다. 원본 `usage`/`timings`를 같이 보관합니다. 서로 다른 수치가 있으면 경고하며 하나로 꾸미지 않습니다. `finish_reason=length`는 출력이 잘렸을 수 있다고 표시합니다.

**비스트리밍 1회 요청**으로 최종 출력 전체를 표시합니다. 글자가 생성되는 즉시 보여주는 스트리밍, 첫 토큰 지연 측정은 이번 범위가 아닙니다.

## 미래 LLM 연결 규약 (지금 설치하는 단계 아님)

- 로컬 OpenAI-compatible **Chat Completions** 프로토콜.
- 준비 확인: `GET /v1/models`.
- 생성: `POST /v1/chat/completions`, `stream:false`.
- 주소는 literal `127.0.0.1`/`::1`로 제한. DNS 이름·외부 클라우드·LAN 다른 기기는 이 버전에서 허용하지 않음.
- 기본 모델 ID: `Qwen3-0.6B-Q5_K_M.gguf`. 실제 서버가 노출하는 ID 또는 alias와 일치시켜야 함. 모델 파일을 자동 선택/설치하지 않음.
- `chat_template_kwargs: {"enable_thinking": false}`를 기본으로 요청. 해당 서버/템플릿이 지원해야 하며 이 옵션만으로 결과 품질·non-thinking 준수가 보장되지는 않음.
- 인증이 필요한 경우 **서버 환경변수 `HUB_LLM_API_KEY`**로만 전달. 브라우저·DB·로그에 키를 노출하지 않음. 이 환경변수 추가가 지금 필수는 아님.
- 현재 문맥 길이·LLM 스레드·GPU 설정은 추후 별도 모델 서버에서 정함. 이 UI의 최대 출력 토큰은 모델 컨텍스트 길이와 다름.
- 입력이 컨텍스트를 초과하면 백엔드 오류를 표시. 입력을 몰래 자르거나 자동 재요청하지 않음.
- `/v1/models` 성공은 서버·모델 ID 조회에 성공했다는 뜻. 실제 생성 성공/실제 Qwen 추론 성능 검증과는 별개.

참고 공식 문서 (2026-09-20 확인):
- llama.cpp server: https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md
- Qwen 공식 GGUF: https://huggingface.co/Qwen/Qwen3-0.6B-GGUF

## 서버 API (전부 관리자 권한)

| Method / path | 기능 |
|---|---|
| GET /api/llm/config | 연결 설정·집계·최근 수동 연결 확인 |
| PUT /api/llm/config | 엄격한 필드 검증 후 설정 저장 |
| POST /api/llm/probe | 저장한 주소의 모델 목록 확인 (생성 없음) |
| POST /api/llm/requests | 저장된 전사에서 요청 스냅샷 생성. enabled=false면 미전송 |
| GET /api/llm/requests | limit 1~100, offset, status, voice_id, query |
| GET /api/llm/requests/{id} | 입력/응답/통계 상세 |
| POST /api/llm/requests/{id}/send | 미전송 기록을 명시적으로 실행 |
| POST /api/llm/requests/{id}/retry | 이전 입력·현재 설정으로 새 요청 기록 생성 |
| POST /api/llm/requests/{id}/cancel | 대기/실행 요청 취소 |
| DELETE /api/llm/requests/{id} | 개별 기록 삭제. 원본 음성·할 일은 유지 |
| GET /api/llm/requests/{id}/export | 개인 요청 기록 JSON 내보내기 |

생성 예:
```json
{
  "request_id": "unique-button-action-id",
  "voice_id": "stored-voice-id",
  "expected_text_sha256": "64-character-sha256-of-stored-text"
}
```
관리자 overview에 `text_sha256`을 추가했으므로 브라우저 HTTP에서도 crypto.subtle 없이 저장본 확인이 가능합니다. 동일 request_id/입력 재전송은 중복 생성하지 않고, 내용이 다르면 409입니다. API가 제공하는 사용자 텍스트만 선택하며 브라우저 임의 텍스트로 우회하지 않습니다.

## 안전장치와 한계

- 한 번에 LLM 요청 1개, 실행+대기 최대4개, 기록 최대1000개. 한도를 넘으면 삭제/내보내기를 요청하며 조용히 기록을 버리지 않습니다.
- 현재 실행 중인 Whisper가 있으면 LLM 시작을 기다립니다. **이후 들어오는 새 녹음까지 완전히 직렬화하는 공용 CPU 스케줄러는 아닙니다.** 첫 성능 시험 때 새 녹음은 LLM 응답 이후에 보내세요.
- 서버 재시작 당시 queued/running 기록은 interrupted로 저장. 자동 재실행 없음.
- 취소는 Room Hub의 HTTP 대기/연결을 끝내는 것. 백엔드가 즉시 계산을 중단하는지는 보장하지 않음.
- 기본 비활성화. 자동 설치/명령 실행/쉘/툴 호출/다른 API 변경 없음.
- 공인 주소 리다이렉트·환경 프록시를 사용하지 않음. 응답 최대512KiB, 요청별 제한10~600초.
- 원본 음성을 삭제해도 이미 보관한 LLM 전사 스냅샷은 남습니다. LLM 화면에서 별도로 삭제해야 하며, 백업에 있는 사본은 별도 관리합니다.
- iPad 표시 권한과 외부 전사 입력 키로는 LLM 기록 조회/실행을 할 수 없습니다. 관리자 쿠키/키만 허용.
- LLM 입력/응답과 내보내기·DB 백업도 개인 데이터. GitHub에 올리지 마세요.

## 설치 이후 되돌리기

코드 패치 도구의 --rollback은 소스만 복원합니다. 새 llm_requests 테이블/기록은 삭제하지 않고 남겨 둡니다. 기존 0.1.3 앱은 이 테이블을 사용하지 않습니다. 재업데이트하면 보관한 기록을 다시 확인할 수 있습니다. 데이터 전체를 이전 시점으로 되돌려야 한다면 별도의 DB 백업 복원이며, 새 일정까지 잃을 수 있으므로 단순 UI 롤백과 혼동하지 마세요.
