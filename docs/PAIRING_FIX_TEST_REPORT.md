# 연결 QR 표시 유지 패치 — 검증 보고서

대상: Room Hub 0.1.1 V35 번들, 패치 ID `0.1.1-pairfix1`.
변경된 실행 파일은 `web/manager.js`, `web/manager.html` 두 개뿐입니다.

## 재현한 원인

`app/main.py`의 연결 생성 엔드포인트는 변경 알림을 WebSocket으로 전송합니다.
구버전 관리자는 그 알림 및 30초 주기 조회 뒤 전체 콘텐츠를 재렌더링하지만,
QR 정보는 화면에만 있고 상태에는 없어 사라집니다.

구버전 프로덕션 JS, 실제 임시 Uvicorn 서버·SQLite·HTTP·WebSocket을 이용했습니다.
타이밍을 재현하도록 관리자 overview 응답 전달을 600ms 지연시켰습니다.
MutationObserver 측정은 다음과 같습니다. 시각은 시험 페이지의 performance.now 기준입니다.

| 시각 | #pairLink 존재 |
|---|---|
| 2341ms | 없음 |
| 2430ms | 표시됨 |
| 3050ms | 사라짐 |

생성 후 약 620ms에 제거되었습니다. 이 시간은 지연을 제어한 시험값이지 V35 실측 지연이 아닙니다.
고친 코드에서는 동일 조건의 존재 상태가 `없음 → 표시됨`으로 유지되었습니다.

중복 제출 차단, 실패 후 재시도, 실제 별도 표시 세션의 일회용 링크 사용,
표시 권한 제한, 만료 시뮬레이션, 실제 연결 해제, 로그아웃 뒤 지연 응답 무시를 포함합니다.
발생한 uncaught JavaScript 오류는 0개였습니다.

## 브라우저 네트워크 검사의 정확한 범위

테스트 환경 Chromium에는 URL 탐색 제한이 있어 실제 관리자 URL로 페이지를 여는
브라우저 E2E를 실행할 수 없었습니다. 제한 설정을 해제하지 않았습니다.

대신 `set_content`로 프로덕션 HTML/CSS/JS를 주입하고, **테스트용 Python 브리지**가
HTTP/쿠키/WebSocket을 실제 임시 Uvicorn 서버로 전달했습니다. QR SVG도 실제 인증된
서버 엔드포인트에서 생성된 것을 이미지로 읽었습니다. 브라우저의 경로 이동은 시험용으로
무시했으며 URL별 쿠키 전달/실제 네트워크 탐색 호환성을 검증한 것은 아닙니다.

원래 처리 로직, 실제 API와 실제 WebSocket 알림은 그대로 사용했지만 네이티브 브라우저
전송 계층 전체를 시험한 것은 아닙니다. 지연 응답·HTTP 실패·클라이언트 시각 오프셋은
명시적으로 주입한 조건입니다. 10분 만료는 실제로 10분을 기다린 시험이 아닙니다.

물리 V35/Termux/PRoot, Windows 관리자 브라우저, iPad Safari 및 카메라 스캔,
집 안 Wi-Fi, 장시간 무인 운영은 이번 환경에서 직접 검증하지 않았습니다.

## 무중단 정적 교체 확인

별도 임시 디렉터리의 구버전 관리자로 Uvicorn을 실행하고, 합성 작업 한 개를 저장한 뒤
`apply.sh`를 실행했습니다. 서버 PID를 유지한 채 새 캐시 키가 있는 `/manager`와 새 JS가
제공되었고 관리자 세션 및 작업은 유지됐습니다. `/healthz`는 정상/0.1.1을 유지했습니다.
이 때문에 이 패치에는 서버 재시작·환경 재설치·DB 복원이 필요하지 않습니다.

## 변경되지 않은 것

서버 Python, 의존성, DB 스키마, 인증 기간(10분/1회 링크), iPad 클라이언트와 완료 권한,
위젯 코드, 미리보기 축소 방지 CSS, V35 서비스·부팅 설정은 변경하지 않았습니다.
