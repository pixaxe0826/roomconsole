# Room Hub 0.1.5 — 명령·조회·일반 대화

> 이 문서는 0.1.5의 최초 구현 기록입니다. 현재 버전의 날짜·조회·품질 정책은 [0.1.6 상세](CONTEXT_016.md)를 우선합니다.

이 버전은 기존 LLM 수신함에 **실제 서버 조회, 변경 미리보기와 확인 실행, 별도 일반 대화 프롬프트**를 추가합니다. 모델 설치/변경은 하지 않습니다. 기본 언어 모델은 사용자가 이미 연결한 Qwen을 그대로 사용합니다.

## 처리 방식

음성 → 기존 Whisper 전사 → 수신함 → 관리자가 전송 → 자동 분기 → 결과입니다. 음성 수신만으로 시작하지 않으며, 기존 요청도 자동 재전송하지 않습니다.

관리자에는 세 모드가 있습니다.

| 모드 | 용도 |
|---|---|
| **자동 분기 · 조회 / 변경 확인 / 대화** | 기본값. 명확한 표현은 규칙으로, 기타 할 일 명령은 스키마 제한 LLM 분석으로 처리합니다. 일반 질문에는 별도 대화 프롬프트를 사용합니다. |
| 일반 대화 | 실제 DB 조회/변경 없이 질문에 답합니다. 작업 명령도 실행하지 않습니다. |
| 기존 직접 전송 | 이전 System 설정과 원래 메시지를 그대로 LLM에 전달하는 비교용 모드입니다. 도구를 실행하지 않습니다. |

공개 API의 mode 생략 기본값은 이전 외부 연동의 호환성을 위해 legacy입니다. 새 관리자 UI는 auto를 명시적으로 전달합니다. 선택은 페이지 메모리에 있으며 새로 열면 auto입니다.

## 지원 예시

| 발화 예시 | 결과 |
|---|---|
| 오늘 할 일에 택배 보내기 추가해? | 물음표만으로 거절하지 않고 날짜/제목을 보여 주며 관리자 확인을 기다림 |
| 내일 할 일에 오후 세 시에 병원 전화하기 추가해 | 내일 15:00의 단일 작업 미리보기 |
| 오늘 남은 할 일 확인해줘 | SQLite의 실제 미완료 작업을 날짜/시간 순으로 표시 |
| 오늘 남은 할 일 확인해서 보고해줘. | 같은 조회. '확인하겠습니다'만 반환하지 않음 |
| 전체 할 일 보여줘 | 모든 날짜의 개수를 세고 첫 50개를 표시. 나머지는 전체 할 일 위젯에서 확인 |
| 오늘 택배 보내기 완료해 | 오늘의 정확히 일치하는 작업을 찾아 완료 미리보기 |
| 오늘 택배 보내기 완료 취소해 | 미완료로 되돌릴 작업 미리보기 |
| 오늘 할 일 전부 완료 처리해 | 현재 대상 목록과 개수를 고정해 확인 |
| 오늘 택배 보내기 삭제해 | 오늘의 해당 회차만 삭제할 미리보기 |
| 지금 몇 시야? | 서버의 요청 기준 시각과 시간대 표시 |
| 오늘 날씨 알려줘 / 내일 날씨 알려줘 | 서버의 저장된 현재 날씨 또는 해당 날짜 예보, 갱신 시각 표시 |
| 이번 주 일정 보여줘 | Room Hub의 해당 기간 할 일. 외부 캘린더 연동 아님 |
| 저녁메뉴 추천해 줘. | Qwen의 일반 대화 경로. 실제 추천 품질은 모델 평가 필요 |

오늘/내일/모레/어제, YYYY-MM-DD, 현재 연도의 M월 D일, 이번/다음 주 요일을 처리합니다. 맨 앞의 상대 날짜가 없으면 요청 기준의 오늘을 사용합니다. 맨날/격주/복합 반복 명령은 이번 버전에서 실행하지 않습니다. 기존 관리자 반복 등록 기능을 사용하세요.

## 변경은 전부 확인 후 실행

추가·완료·완료 취소·삭제는 **항상 관리자 화면의 '확인한 내용 실행' 버튼 이후** 실행됩니다. 읽기는 요청 시 바로 처리합니다. iPad에는 새 쓰기 권한이나 확인 버튼을 추가하지 않았습니다. iPad의 기존 할 일 완료 버튼은 그대로 유지합니다.

미리보기에는 정확한 날짜·시간·제목, 일괄 대상 목록, 동일 작업이 이미 있는지 여부를 표시합니다. 확인 유효시간은 10분입니다. 작업의 내용/버전/완료 상태나 서버 시간대가 달라지면 실행하지 않습니다. 미리보기 이후 새로 생긴 작업을 일괄 대상에 몰래 추가하지 않습니다. 일괄 변경은 100개까지입니다.

같은 요청을 확인 버튼으로 두 번 보내거나 실행한 기록에서 재요청해도 같은 동작을 다시 적용하지 않습니다. 실행 영수증과 변경은 한 DB 트랜잭션으로 기록됩니다. 별도 음성에서 같은 작업을 다시 등록하려 하면 중복 후보를 미리 보여 주며, 관리자가 확인하면 의도된 두 번째 등록은 가능합니다.

이 버전의 삭제는 확인한 해당 날짜의 항목만 대상으로 하며, 전체 반복 시리즈를 삭제하지 않습니다. 같은 제목이 여러 개 있거나 대상을 못 찾으면 추측하지 않고 확인을 요청합니다. 부정/인용/조건/복합·반복 명령은 안전하게 보류합니다.

## 원본·LLM·실행 결과를 구분

원본 전사문을 수정하지 않습니다. 공백/NFC를 정리하고 인식 가능한 요청 종결어 뒤의 문장부호만 정규화합니다. '추가해?'와 '추가해도 될까?'를 같은 무조건 실행으로 취급하지 않습니다.

명확한 명령은 LLM을 호출하지 않습니다. LLM 분석이 필요한 경우 JSON Schema를 요청하되, 올바른 JSON이라는 사실을 권한으로 취급하지 않습니다. intent 허용목록, 원문에 있는 제목/날짜/시간, 단일/전체 범위, 실제 대상과 버전을 서버가 검증합니다. 모델이 임의 SQL·쉘 명령·URL·작업 ID를 실행할 수 없습니다.

Manager의 새 상세 패널에는 원본/정규화/분기/intent/arguments/검증/미리보기/실행결과/실제 LLM API 호출을 남깁니다. 스키마나 모델 분석이 실패하면 '요청 확인 필요'로 남으며 자동 재시도·변경하지 않습니다.

일반 대화는 기존의 '권한 없음' 위주 검토 프롬프트와 분리합니다. 같은 Qwen 서버를 사용하며 새 모델을 띄우지 않습니다. 한 요청에 최대 한 번 모델을 호출합니다. 명령 파서가 chat.general로 판단하면 현재 버전은 추가 자동 재호출 없이 일반 대화 모드로 다시 보내도록 안내합니다. 대화 기록 전체를 자동으로 모델에 보내는 다중 턴 기능은 없습니다.

## 측정 표시

규칙 처리 시 LLM 토큰/생성 속도는 `—`입니다. 요청 처리 시간만 표시합니다. 0.00초처럼 반올림될 수 있으며 LLM이 빨리 생성한 수치가 아닙니다. 파서 요청은 실제 모델 JSON 생성 통계가 남지만, 최종 서버 조회문·실행 결과의 글자 수를 모델 토큰으로 계산하지 않습니다. 일반 대화와 legacy는 기존 백엔드 통계를 표시합니다. 첫 토큰 지연(TTFT)은 측정하지 않습니다.

## 권한·데이터·기존 이력

이전 0.1.4 요청 스냅샷은 변하지 않습니다. 개선된 방식으로 시험하려면 auto 모드에서 **'현재 설정으로 새 요청'** 또는 음성 수신함에서 다시 전송하세요. 기존에 저장해 둔 미전송 항목의 '저장된 입력 전송'은 이전 스냅샷 의미를 보존합니다.

LLM 응답 위젯은 처리된 로컬 조회·미리보기·확인 후 실행 결과도 보여 줍니다. 위젯이 배치된 공유 화면들에 원문과 최종 결과가 공개됩니다. 확인 토큰·대상 내부 ID·System·원본 백엔드 JSON은 표시용 API로 전송하지 않습니다.

DB에 assistant_runs, assistant_effects 두 테이블만 추가하며 기존 테이블·설정·모델은 초기화하지 않습니다. LLM 기록 삭제 시 상세 assistant_runs는 삭제되지만, 재실행 방지용 assistant_effects 영수증은 남습니다. 영수증에는 실행시각·작업 ID·간단한 결과 문장이 포함되어 개인정보로 취급합니다. DB 백업을 공개 저장소에 올리지 마세요.

## 실제 모델 선택 시험

`bash deploy/termux/assistant-selftest.sh`는 기존 localhost:8090 모델에 합성 한국어 일반 질문과 JSON 분석 요청을 각각 한 번 보냅니다. Room Hub 작업/설정/전사문에는 접근하지 않습니다. 결과는 data/assistant-model-probe.json입니다. 인식 가능한 응답과 스키마/원문 일치의 기초 점검일 뿐 전반적 모델 정확도 보장은 아닙니다.

이 설치 환경에서 실제 Qwen 추론은 실행하지 못했습니다. 규칙 경로와 DB 변경·확인 안전성은 테스트했으며 일반 대화·모호한 명령의 실모델 품질은 V35에서 확인해야 합니다.
