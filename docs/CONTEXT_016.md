# Room Hub 0.1.6 — 시간·데이터 기반 요청 처리

## 목적과 경계

0.1.5 + STT 정확도 패치에서 업그레이드합니다. Whisper **multilingual Base / ko / 6 threads / careful(beam 5)**의 코드·모델·녹음·설정은 변경하지 않습니다. Qwen3-0.6B-Q5_K_M, llama-server CPU 6T, 컨텍스트 1024, 8090 서비스도 재설치하거나 설정 파일을 바꾸지 않습니다. 새 명령/대화 요청의 프롬프트와 샘플링 매개변수만 애플리케이션이 경로별로 지정합니다.

핵심은 모델을 더 크게 만들기보다 서버가 시간, 조회 조건, 데이터와 실행 권한을 책임지는 것입니다. 메모 CRUD, 알람 예약, MCP, 음성에 의한 임의 실행, 다중 턴 지시 대상을 이번에 구현하지 않았습니다. 기존 메모 위젯은 표시용입니다.

## 고친 증상

| 입력 | 새 동작 |
|---|---|
| 오늘, 남은 할 일 확인해 | 날짜 경계의 쉼표를 읽고 실제 미완료 목록 조회. 모델 미호출 |
| 오늘 할 일 뭐 남아있어? | 같은 미완료 서비스 사용 |
| 내일 뭐 해야 돼? | 내일의 미완료 목록 조회 |
| 내일 할 일 브리핑해 줘. | 내일 전체 작업을 날짜·시간순으로 정확히 표시. 생성형 장문 요약 아님 |
| 내일 **남은** 할 일 브리핑해 줘. | 내일 미완료 목록만 표시 |
| 9월 21에 남은 일 알려줘. | 요청 기준 연도의 9월 21일, 미완료 조회. ‘일’ 생략 허용 |
| 이번 주 / 다음 주 남은 할 일 알려줘 | ISO 월~일 범위 조회. iPad의 일~토 날짜 줄은 그대로 |
| 네, 뭐 해야 돼? | ‘네’를 ‘내일’로 바꾸지 않고 날짜 확인 |
| 9월 21에 남은 애 말려줘 | 오인식인지 불명확하므로 조회를 만들어 내지 않음 |
| 새 메모 저장 / 알람 설정 | 아직 미연결이라는 안내. 저장·예약했다고 주장하지 않음 |

‘할 일’은 전체 상태, ‘남은/미완료/해야 할’은 미완료, ‘완료된/끝낸’은 완료 상태입니다. ‘전체 할 일’만 지정하면 전체 날짜, ‘오늘 전체 할 일’은 오늘의 전체 상태입니다. 새로운 제목의 어휘·숫자·부정·조건·인용은 임의로 고치지 않습니다. ‘내일 뭐 먹어야 돼?’는 일반 대화입니다.

## 1. 공통 시간 서비스

`app/clock_service.py`에서 timezone-aware ISO 시각과 IANA 시간대를 사용합니다. 모델이 오늘·내일 날짜를 계산하지 않아도 되도록 요청마다 local_at, today, tomorrow, weekday를 서버가 만듭니다.

- 요청의 기준일은 **새 요청이 생성된 시각**에 고정합니다. 원본 음성 접수 시각도 별도 보존합니다. 녹음 시각 기준 의미로 자동 소급하지 않습니다.
- 원문 날짜(evidence)와 실제 계산값(start/end)을 따로 저장합니다. ‘내일’을 동등한 ISO 날짜로 반환해도 통과하고, 다른 날짜면 거부합니다.
- 연도 없는 월/일은 요청 기준 **현재 연도**입니다. 과거 날짜를 자동으로 다음 해로 넘기지 않습니다. 연말·내년은 정확한 연도를 말하세요.
- 오늘·내일·모레·어제, ISO/한국어 날짜, 이번/다음 주, 이번/다음 달, 요일을 지원합니다. 여러 서로 다른 날짜나 `부터~까지` 자유 범위는 확인 대상으로 남깁니다.
- ‘지금 몇 시야?’는 실제 실행 시각을 읽습니다. 재시도한 과거 기록을 최신 데이터처럼 바꾸지 않습니다.
- 날짜가 바뀌거나 기준이 15분 이상 지난 요청은 새 요청으로 갱신을 요구합니다(현재 시각 단순 조회 예외). 시간대 변경도 감지합니다. 변경 승인 유효시간은 기존 10분이며 자정을 넘긴 승인도 거부합니다.
- `/api/clock`은 인증된 viewer에만 제공합니다. 별도 인터넷 시간 서버를 호출하거나 OS 시간을 수정하지 않습니다. `clock_sync_verified:false`이며 **V35 자동 날짜·시간 설정 자체의 정확성은 별도 조건**입니다.

## 2. 서버가 소유하는 원문 조건

`app/command_semantics.py`가 날짜·미완료·완료·전체 조건의 근거를 추출합니다. LLM 제안은 형식뿐 아니라 이 조건과 일치해야 합니다. ‘남은’인데 모델이 all/completed를 반환하면 그대로 실행하지 않고 명확히 거부합니다. 원문의 날짜가 있는데 읽기 제안에서 빠진 경우 서버가 원문 날짜를 사용합니다. 변경 제안에서 날짜가 빠지거나 달라지면 다시 확인합니다.

쉼표 정리는 **날짜/명령 경계에 한정**합니다. 제목 속 쉼표·숫자·인용문을 전역 삭제하지 않습니다. 모델이 제목·시간·일괄 범위를 지어내거나, 변경 요청을 조회로 축소해도 거부합니다. 제목 fuzzy 자동완료는 하지 않습니다. 현재 카테고리·우선순위·제외 조건 등 미지원 필터는 무시하지 않고 관리자 목록 사용을 안내합니다.

## 3. 실제 할 일 조회와 UI 연결

`Store.query_tasks()`를 공통 읽기 서비스로 만들었습니다. `/api/state`의 위젯 목록과 비서가 동일한 서비스·SQLite를 사용합니다. count/items/revision을 동일 DB 읽기 트랜잭션에서 얻고 source, range, status, as_of, returned, truncated를 기록합니다.

- 모델이 기억한 목록이 아니라 **요청 때 실제 SQLite 조회**입니다.
- 조회 성공 0개 / 읽기 실패 / 조회하지 않음을 구분합니다. 실패를 ‘할 일이 없다’로 바꾸지 않습니다.
- 요청 기록에는 최초 50개를 보존·표시하고 전체 개수 및 잘림을 명시합니다. 전체 데이터는 기존 할 일 화면을 이용합니다.
- 과거 요청 기록은 당시 조회 스냅샷입니다. 새 데이터는 새 요청으로 조회합니다.
- 실제 쓰기는 여전히 서버가 정확한 ID/version을 고정한 미리보기를 생성하고 **관리자 확인 후 한 트랜잭션으로 실행**합니다. 중복 확인·재요청은 반복 실행하지 않습니다.
- 기존 websocket 무효화 알림과 클라이언트 재조회 흐름을 사용합니다. 새 전송 프로토콜이나 polling 간격 변경은 없습니다.

## 4. 기능 등록부

`app/capabilities.py`는 승인된 도구 이름·입출력·읽기/쓰기·핸들러·승인 정책을 한곳에서 정의합니다. LLM에게 제공하는 허용 도구 목록과 서버 허용 목록이 같은 근거를 사용합니다.

현재 등록: todo.list, calendar.query, time.query, weather.query, todo.create, todo.complete, todo.uncomplete, todo.delete.

관리자만 `/api/assistant/capabilities`, `/api/assistant/tasks`에 접근할 수 있습니다. 조회용 Client에 관리자 권한이나 일반 실행 API를 열지 않습니다. 추가 기능은 신뢰된 서버 서비스와 handler, schema, permission, tests가 필요합니다. **위젯 폴더를 넣었다고 임의 코드를 실행하는 구조가 아닙니다.** notes/alarms는 unavailable로 명시합니다. 등록부는 확장 토대이고, 아직 메모/알람 실행기는 아닙니다.

## 5. 일반 대화와 반복 출력

자동/일반대화 경로: non-thinking, max_tokens=min(기존상한,128), temperature 0.7, top_p 0.8, top_k 20, min_p 0, presence_penalty 1.0. 명령 분석: non-thinking, max_tokens=min(기존상한,256), temperature 0, JSON schema. 기존 직접전송(legacy) 경로의 생성 설정은 보존합니다.

일반 대화에 과제 DB를 무조건 넣지 않습니다. 알려진 개인 작업 문의는 도구/확인 경로로 보내고, 일반 대화에는 조회·실행했다고 주장하지 않도록 안내합니다. 자연어 분류는 여전히 제한적이며 이 가드가 모든 환각을 막는다는 뜻은 아닙니다.

응답 수신 후 `app/response_quality.py`가 반복 구절/입력 에코/토큰 한도 잘림/예상치 못한 think태그를 점검합니다. 이상 시 `needs_clarification`으로 기록하고 Client에는 안전한 안내만 표시합니다. 실제 모델 원출력·통계는 **관리자 호출 기록**에 그대로 남습니다. 출력에 임의 문장을 지어 대신 답하지 않습니다. 자동 재시도하지 않습니다.

**스트리밍 중단은 이번 범위 밖입니다.** 128토큰 제한으로 상한을 낮췄지만, 후처리 검사는 이미 소비한 생성 시간을 되돌리지 않습니다. 0.6B의 한국어 품질이나 무오류를 보장하지 않습니다.

## 6. UI와 데이터 보존

관리자에 연결된 기능 목록, 현재 서버 시각·시간대, 요청 기준 로컬 날짜, 원문 날짜 → 해석 범위, SQLite 조회 근거·시각·전체/표시 개수, 품질 거부 이유를 표시합니다. 규칙 처리 기록은 Qwen 실행으로 오해하지 않도록 ‘Room Hub 서버·모델 미호출’로 표시합니다.

Client 위젯 코드는 변경하지 않으며, 기존 서버 DTO를 통해 실제 결과 또는 품질 안내를 보여줍니다. 관리자의 system/payload/raw model/확인 권한을 Client에 넘기지 않습니다.

이전 기록은 보존합니다. 과거 준비된 자동 요청(protocol 1)은 현재 로직으로 몰래 재해석하지 않고 새 요청 생성 안내를 합니다. 이전에 실제 승인 실행한 receipt는 계속 중복 방지를 담당합니다.
